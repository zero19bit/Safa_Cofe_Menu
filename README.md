# کافه صفا — نسخه ۲

این پروژه، منوی مشتری، پنل مدیریت و API سرور را برای استقرار روی Vercel در اختیار شما می‌گذارد. محصولات، دسته‌ها، اطلاعات کافه، نشست‌های مدیریت و فایل‌های آپلودشده در Supabase نگهداری می‌شوند. هیچ دادهٔ منو یا رمز عبوری در localStorage، sessionStorage یا IndexedDB ذخیره نمی‌شود. فقط کوکی امن نشست مدیریت در مرورگر وجود دارد.

## وضعیت این نسخه

- لوگوی اصلی صفا از فایل ارسالی حفظ شده و در هدر، فوتر، آیکون مرورگر و صفحهٔ `/qr` قرار دارد.
- نام و عنوان صفحات، رنگ‌های سبز و کرم، فونت فارسی محلی و طراحی واکنش‌گرا بازسازی شده‌اند.
- مدیریت محصولات، چند قیمت برای یک محصول، قیمت ویژه، قیمت روز، محصول بدون قیمت و فعال/غیرفعال کردن آماده است.
- مدیریت دسته‌ها و ترتیب، اطلاعات کافه، آپلود/تغییر/حذف تصویر، نسخه پشتیبان JSON و تولید QR آماده است.
- فایل SQL ایجاد دیتابیس، ساخت حساب مدیر و واردکردن یک‌جای منو در پروژه موجود است.
- اتصال به حساب واقعی Supabase و انتشار واقعی روی Vercel هنوز انجام نشده؛ اطلاعات یا دسترسی این حساب‌ها همراه فایل نبود.
- عکس منوی چاپی همراه ZIP نبود. ۱۹ محصول فایل قبلی نمونه‌اند؛ صحت نام، توضیح و قیمت‌های آن‌ها تأیید نشده است. هیچ محصول نمونه‌ای به‌صورت خودکار در دیتابیس واقعی وارد یا منتشر نمی‌شود.
- شماره تماس، نشانی، اینستاگرام و ساعت کار خالی‌اند تا اطلاعات ساختگی نمایش داده نشود.
- آزمایش روی آیفون، اندروید و تبلت واقعی و بررسی بصری با مرورگر هنوز انجام نشده است؛ جزئیات آزمایش‌های خودکار در `TEST_REPORT.md` آمده است.

## شروع سریع

نیازمندی: Node.js 24 و npm. پوشهٔ پروژه را باز کنید و اجرا کنید:

```bash
npm ci
npm run dev
```

- منوی مشتری: `http://localhost:3000/`
- پیش‌نمایش با داده‌های نمونه: `http://localhost:3000/?demo=1`
- پنل: `http://localhost:3000/admin`
- صفحهٔ اسکن QR: `http://localhost:3000/qr`

پیش‌نمایش نمونه با نوار هشدار مشخص می‌شود و ویرایش آن در مرورگر ذخیره نمی‌شود. بدون تنظیم دیتابیس، پنل ورود فعال نمی‌شود و صفحهٔ اصلی وضعیت آماده‌نبودن منوی آنلاین را نشان می‌دهد. این رفتار از انتشار ناخواستهٔ نمونه‌ها جلوگیری می‌کند.

فایل‌ها با دوبار کلیک و پروتکل `file://` اجرا نمی‌شوند؛ این نسخه API سرور دارد. پوشهٔ `dist` خروجی آمادهٔ ساخت است، اما برای قابلیت‌های مدیریت باید کل پروژه استقرار یابد.

## راه‌اندازی Supabase

۱. یک پروژهٔ Supabase بسازید.

۲. تمام محتوای `supabase/schema.sql` را در SQL Editor همان پروژه اجرا کنید. جدول‌ها، توابع تراکنشی، مجوزها، محدودیت‌های دیتابیس و bucket تصاویر ساخته می‌شوند. اجرای دوبارهٔ این فایل محصولات موجود را پاک نمی‌کند.

۳. فایل `.env.example` را به `.env` کپی کنید و این مقادیر را تنظیم کنید:

| متغیر | مقدار |
| --- | --- |
| `SUPABASE_URL` | نشانی HTTPS پروژهٔ Supabase |
| `SUPABASE_SECRET_KEY` | کلید محرمانهٔ سرور از نوع `sb_secret_...` |
| `SESSION_SECRET` | یک مقدار تصادفی، با حداقل ۳۲ نویسه |
| `APP_ORIGIN` | برای اجرای محلی `http://localhost:3000`؛ برای تولید نشانی نهایی سایت |

اگر فقط کلید قدیمی `service_role` دارید، آن را در `SUPABASE_SERVICE_ROLE_KEY` قرار دهید و `SUPABASE_SECRET_KEY` را حذف کنید. هیچ کلید محرمانه‌ای را در فایل‌های `public`، `dist`، کد مرورگر یا مخزن عمومی قرار ندهید.

برای تولید `SESSION_SECRET`:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

۴. در تنظیمات Authentication، ورود Email/Password فعال و ثبت‌نام عمومی غیرفعال باشد. حساب مدیر از طریق فرمان بعد ساخته می‌شود؛ ثبت‌نام باز برای منوی کافه نیاز نیست. تنظیمات ایمیل، password policy یا MFA نباید ورود مستقیم Email/Password این نسخه را مسدود کنند.

## ساخت مدیر

```bash
npm run create-admin
```

فرمان در ترمینال تعاملی نام کاربری، ایمیل و رمز را می‌گیرد. رمز نمایش داده نمی‌شود. نام کاربری ۳ تا ۶۴ نویسه و شامل حروف کوچک انگلیسی، عدد یا `_ . -` است. رمز باید حداقل ۱۲ نویسه و حداکثر ۷۲ بایت UTF-8 باشد. ایمیل را ایمیلی واقعی و تحت کنترل خودتان وارد کنید.

ساخت حساب از Supabase Auth انجام می‌شود؛ Supabase رمز را با bcrypt و salt نگه می‌دارد. پروژه هیچ رمز عبور پیش‌فرضی ندارد و حساب مدیر از مرورگر ساخته نمی‌شود. حساب باید هم در Auth و هم در جدول `admins` ثبت شده باشد.

برای قطع فوری دسترسی یک مدیر، مقدار `active` رکوردش در جدول `admins` را false کنید. برای ابطال همهٔ نشست‌ها:

```sql
delete from public.admin_sessions;
```

در این نسخه بازیابی یا تغییر رمز از داخل پنل وجود ندارد. اگر رمز را از مدیریت Auth تغییر می‌دهید، نشست‌های آن مدیر را نیز حذف کنید:

```sql
delete from public.admin_sessions
where admin_id = 'شناسه UUID واقعی مدیر';
```

## ورود منوی واقعی

پس از اتصال، در `/admin` دسته‌ها و محصولات واقعی را اضافه کنید. هر قیمت به تومان و عدد صحیح وارد می‌شود؛ صفر با «بدون قیمت» تفاوت دارد.

| نوع | داده |
| --- | --- |
| عادی | `price_type: fixed` و `price` عددی |
| ویژه | `special_price` کمتر از `price` |
| چندقیمتی | `price_type: fixed`، قیمت اصلی null و `variants` شامل گزینه‌ها |
| قیمت روز | `price_type: daily`؛ قیمت‌ها null و گزینه‌ها خالی |
| بدون قیمت | `price_type: unpriced`؛ قیمت‌ها null و گزینه‌ها خالی |

برای ورود یک‌جای منو، ساختار `data/menu-template.json` را با اطلاعات تأییدشده پر کنید و اجرا کنید:

```bash
npm run import-menu -- data/real-menu.json
```

واردکردن دسته‌ها و محصولات در یک تراکنش انجام می‌شود؛ خطای یک محصول کل واردکردن را برمی‌گرداند. شناسه‌های متنی دسته‌ها به UUID تبدیل می‌شوند. فایل پشتیبانِ همین پروژه، شناسه‌های UUID را حفظ می‌کند و رکوردهای همان شناسه را به‌روزرسانی می‌کند. اجرای مکرر یک فایل با شناسهٔ متنی تضمین جلوگیری از تکرار نیست؛ برای به‌روزرسانی بعدی از نسخهٔ پشتیبان UUID استفاده کنید. تصاویر فایل پشتیبان باید از قبل در همان پروژه موجود باشند. تنظیمات انتشار منو با این فرمان تغییر نمی‌کند.

برای آزمایش اختیاری با نمونه‌های قبلی:

```bash
npm run import-menu -- data/sample-menu.json --sample
```

تمام محصولات نمونه در این حالت غیرفعال وارد می‌شوند. پیش از فعال‌کردن هر محصول، نام و قیمت آن را با منوی واقعی تطبیق دهید.

پس از تکمیل اطلاعات، در بخش «اطلاعات کافه»، گزینهٔ «منو برای مشتریان منتشر شود» را فعال و ذخیره کنید.

## انتشار روی Vercel

۱. کل پوشهٔ پروژه را از طریق مخزن Git در Vercel وارد کنید، یا در همین پوشه اجرا کنید:

```bash
npx vercel
```

۲. پروژهٔ Vercel از نوع Other است. تنظیمات ساخت در `vercel.json` وجود دارد:

- Node.js: نسخه ۲۴
- Install: `npm ci`
- Build: `npm run build`
- Output: `dist`

۳. متغیرهای `SUPABASE_URL`، کلید محرمانهٔ Supabase و `SESSION_SECRET` را در Environment Variables محیط Production قرار دهید. نشانی اولیهٔ اختصاص‌یافته را دریافت کنید، سپس `APP_ORIGIN` را دقیقاً برابر نشانی نهایی HTTPS، بدون مسیر `/admin` یا `/qr` بگذارید. بعد از تنظیم یا تغییر متغیرها، دوباره Deploy کنید.

```bash
npx vercel --prod
```

۴. از یک مرورگر وارد `/admin` شوید، قیمت را تغییر دهید و از مرورگر یا گوشی دیگری `/` را بررسی کنید. صفحهٔ مشتری هر ۳۰ ثانیه هنگام بازبودن صفحه و با برگشت فوکوس، منو را دوباره دریافت می‌کند. درخواست‌های API کش نمی‌شوند.

۵. اگر مالک دامنهٔ `safa.ir` هستید، آن را در Domains پروژهٔ Vercel متصل و `APP_ORIGIN` را `https://safa.ir` کنید، سپس دوباره Deploy کنید. تغییر نشانی به‌تنهایی مالکیت یا اتصال DNS دامنه را ایجاد نمی‌کند. این نسخه اتصال همین دامنه را فرض نکرده است.

۶. پنل مدیریت فقط از همان `APP_ORIGIN` اجازهٔ نوشتن می‌دهد. Preview Deployments برای ورود به پنل به نشانی و متغیرهای Preview مخصوص خود نیاز دارند؛ نسخه‌های Preview را به Production origin وصل نکنید.

## QR

در پنل آنلاین، بخش «کد QR» را باز کنید. QR از نشانی جاری سایت و مسیر `/qr` ساخته می‌شود؛ سرویس خارجی یا نشانی ثابت فرضی استفاده نمی‌شود. PNG با اندازهٔ ۱۰۰۰ پیکسل قابل دریافت است و گزینهٔ چاپ نیز وجود دارد. لوگو کنار QR قرار می‌گیرد و روی مربع‌های قابل اسکن نمی‌افتد.

برای چاپ، QR را روی دامنهٔ نهایی بسازید و با آیفون و اندروید اسکن کنید. QR ساخته‌شده روی localhost برای مشتریان قابل استفاده نیست.

## امنیت و ساختار

- احراز هویت Email/Password روی سرور با Supabase Auth انجام می‌شود.
- نشست برنامه یک توکن تصادفی ۲۵۶ بیتی است؛ دیتابیس فقط SHA-256 آن را نگه می‌دارد. خروج، نشست سروری را حذف می‌کند.
- کوکی تولیدی `__Host-safa_session` با `Secure`، `HttpOnly` و `SameSite=Strict` تنظیم می‌شود.
- حداکثر نشست ۸ ساعت و مهلت عدم فعالیت ۳۰ دقیقه است.
- هر نوشتن به نشست معتبر، مدیر فعال، مبدأ مجاز و توکن CSRF نیاز دارد.
- محدودیت ورود در دیتابیس و به‌صورت اتمی است: ۵ درخواست هر نام کاربری در ۱۰ دقیقه و ۳۰ درخواست هر IP در ۱۰ دقیقه. درخواست موفق هم از بودجهٔ تلاش ورود کم می‌کند.
- RLS و مجوزهای جدول‌ها و RPCها دسترسی مستقیم `anon` و `authenticated` را مسدود می‌کنند. کلید قدرتمند Supabase فقط در سرور است.
- ویرایش‌ها `if_match` می‌خواهند تا اطلاعات قدیمی روی قیمت جدید نوشته نشود.
- حجم تصویر حداکثر ۲ MiB، نوع پذیرفته‌شده JPG/PNG/WebP و امضای باینری فایل نیز بررسی می‌شود؛ SVG پذیرفته نمی‌شود.
- محدودیت‌های foreign key حذف تصویر در حال استفاده و دستهٔ دارای محصول را حتی با درخواست هم‌زمان متوقف می‌کنند.
- صفحات مدیریت برای موتورهای جست‌وجو noindex هستند. صفحهٔ HTML ورود قابل بارگیری است؛ داده و API مدیریت بدون مجوز قابل دریافت نیست.

| مسیر | روش | کاربرد |
| --- | --- | --- |
| `/api/menu` | GET | منوی عمومی منتشرشده |
| `/api/admin` | GET | همهٔ محصولات، دسته‌ها، تنظیمات و تصاویر برای مدیر |
| `/api/auth/login` | POST | نام کاربری و رمز |
| `/api/auth/session` | GET | وضعیت نشست و CSRF |
| `/api/auth/logout` | POST | ابطال نشست و خروج |
| `/api/product` | POST / PUT / DELETE | مدیریت محصول |
| `/api/category` | POST / PUT / DELETE | دسته، ترتیب و وضعیت |
| `/api/settings` | PUT | اطلاعات کافه و انتشار |
| `/api/image` | POST / DELETE | آپلود و حذف تصویر |

فایل‌های frontend در `public`، کد سرور در `server`، ورودی‌های Vercel در `api`، ساختار SQL در `supabase`، و فرمان‌ها در `scripts` هستند.
